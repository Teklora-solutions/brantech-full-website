# Automatic embedding recovery and managed model migration

## Intent and invariants
User requested mostly automatic operation plus admin controls. Keep source/original files, local browser previews, extraction, external-processing clearance, public approval and embedding readiness independent. Existing preview work must remain intact. Never run production embeddings, change the live model or deploy as part of implementation tests.

An immutable embedding profile is an EmbeddingSpace (Google model, dimensions, input protocol, API backend). Google model family remains `gemini` for clearance; `vertex` and `developer_api` describe distinct access/billing routes. New admin profiles default to Vertex. Legacy profiles use the explicit `configured` backend and resolve `EMBEDDING_BACKEND` (default/Compose production: `vertex`); new administrator profiles pin their selected backend. Changing the legacy environment setting is an explicit operator action, not error-triggered fallback. No silent endpoint/provider/model fallback. Credentials stay server-side and are never accepted or displayed in forms, persisted in job metadata, or included in logs. Model 2 uses instruction-prefixed queries/documents without task_type; model 001 supports task types. Legacy input protocol is preserved for existing spaces.

## Durable work and automatic recovery
Each document/space has one durable work record with source-hash snapshot, lease token, attempt count, bounded next-retry time, safe error category and terminal blocked/exhausted state. Checkpoint each successful vector immediately. Retries skip current-hash vectors, revalidate source and library clearance/current-version/deletion eligibility before external calls and before writes, and never treat malformed/zero/nonfinite/wrong-width vectors as ready. Distinguish transient timeout/network/rate-limit/server failures from authentication/permission/model/configuration/structural failures. Backoff includes jitter and respects bounded provider retry guidance. Broker failure leaves pending durable work; periodic maintenance resumes queued work and recovers expired leases. A four-work-item dispatch window and shared per-profile cooldown/credential pause avoid retry storms and broker duplication. Avoid logging provider text. A timeout/crash can leave an uncertain in-flight request and therefore require a repeat of that one source; provider APIs do not offer exactly-once billing. Completed checkpoints are retained.

Library extraction persists chunk/source records before vector generation, hidden from retrieval until initial processing is ready. Embedding retry does not require re-extracting or discarding successfully embedded chunks. Library candidate re-indexing uses its own cleared/current-version path; generic reembed continues to exclude protected scopes.

## Model change lifecycle
Administrator creates an explicit target profile with optional activate-when-ready consent. Work builds in the background while old active space serves queries. A fixed-text endpoint/model preflight must pass before candidate corpus calls. Coverage counts include current-hash managed generic source documents and current, cleared, extraction-checkpointed library chunks (including initial processing still awaiting vectors); never count excluded private documents as migrated. Library source text/hash/scope must match its immutable chunk. Generic writes/recall/forget cannot bypass library policy through a scope label, model identity or mistagged backing record. Recheck clearance after credential refresh, and refresh actor authorization after slow semantic-query generation. Pausing/resuming/retrying is explicit and audited. Maintenance reconciles new/changed documents before completion. Query clients resolve from the selected space, not a global model-name override. Model/dimension/protocol/backend edits to a populated profile are not an admin form operation.

Activation requires complete eligible coverage, no unresolved source/worker failures, a successful sanitized query probe and usable vector index where supported. Fence coverage/activation against concurrent canonical source writes; publish a single active-space change atomically. Retain old vectors and support rollback after checking current-source coverage. Guard the legacy CLI activation path with the same library coverage checks; force must not bypass privacy/model/coverage safety. Rollback is not a stale index flip if sources have changed.

## Admin and operations
Under Knowledge Library, authorized library administrators can see active model/backend/dimensions, migration progress, safe failure categories, retry counts and next-attempt time; choose model/backend/dimensions; start/pause/resume/retry; and activate or request a validated rollback. POST+CSRF, server-side capability checks, private/no-store responses, paginated failure lists and metadata-only audit. Ordinary staff retain existing document retry/download/preview rights but cannot change global embeddings. No raw keys or private bodies in administrative error reporting.

Use existing dedicated library_processing workers for bounded per-document work and a one-minute periodic coordinator on the default queue. Keep historical unversioned `KnowledgeDocument` vectors isolated: no trustworthy model provenance/processing clearance means no automatic remote replay. Preserve discoverability with explicitly reported lexical fallback; new authorized published articles enter managed spaces with stable article-ID identity. Mount configured Vertex credentials read-only on the dedicated worker. No silent use of Developer API credits in production. Automatic activation requires explicit administrator consent on creating the migration; otherwise stop at ready for review. UI must state costs/credit usage are possible and list-price estimates do not prove credit balance.

## Verification
Offline fake-provider tests for client routing/protocols/vector validation, checkpoint recovery, backoff/permanent errors, duplicate leases, broker outage, cancellation/revocation/source changes, all-corpus coverage, cutover/rollback, legacy CLI guards and CSRF/ACL. Test migrations on isolated databases and inspect admin browser flow with fake providers. Retain existing library/task/AI workflows tests. Real Vertex quality/cost evaluation remains a separate authorized experiment, not a prerequisite to test framework correctness or a claimed completed result.
